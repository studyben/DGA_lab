## Decisions / interfaces

- Shared identity service owns users/roles/permissions/sessions/audit, Argon2id password hashes, random opaque cookie sessions whose SHA256 hashes alone are stored. Cookies HttpOnly/SameSite=Lax/path=/, Secure by default; local Compose explicitly disables Secure for loopback HTTP. Absolute session lifetime 8h configurable; check account status/current permissions every request, not stale cookie claims.
- Login returns public identity/roles/permissions, must_change_password, CSRF token; no session token in JSON. Failed login returns generic 401 and audited result, including unknown usernames without fabricating actor IDs. Five consecutive failures temporarily throttle the account for 15 minutes (independent of manually LOCKED/DISABLED status). All credential mutations serialized with per-user DB row locks; failures commit audit before returning errors.
- POST /api/auth/login, POST /api/auth/logout, POST /api/auth/password; GET /api/auth/session. Mutations require allowlisted Origin; authenticated mutations also require X-CSRF-Token tied to session. Password 15–128 characters, no trimming, reject reuse on change; verified current password required. Change revokes all existing sessions and issues a new session atomically. Pending-password sessions cannot enter business APIs. Session logout is idempotent for missing/revoked sessions but requires allowed Origin.
- Auth public immutable ActorContext + require_permission; business public entry checks module read capability. GET /api/modules requires completed authentication and lists allowed modules; GET /api/{assets,laboratory,condition-analysis}/access calls each module's public interface and returns verified actor/module. This is access context, not pretend business CRUD. GET /api/health remains anonymous for infrastructure probes.
- Minimal capabilities: assets.read/write, laboratory.read/write/finalize, analysis.read/write, identity.manage, audit.read. System admin all; Asset Manager assets read/write + analysis read; lab admin assets read, lab read/write/finalize, analysis read; analyst assets read, lab read/write, analysis read; field engineer assets read + analysis read; management read-only assets/lab/analysis read. This conservative initial mapping is documented, not a permissions editor. Future operations enforce their capability at owning public interfaces.
- Trusted CLI bootstrap creates the first admin only, reading secret from interactive prompt, no default shipped password. Admin-only public provisioning/status/role methods support operators and test setup without a management UI or open HTTP provisioning endpoint. Public audit query requires audit.read and never returns passwords/session/CSRF secrets. Audit stores claimed username + nullable resolved actor for failures; timestamps UTC.
- Frontend auth provider/gate checks server session before rendering business shell, shows checking/error/retry/login/first-change/forbidden states; safe local return path only. Accessible forms retain SUNGROW. Permission mechanism owns visibility/disabled affordances; route requirements own mapping, server remains authoritative. Logout and session checks on focus/interval handle stale tabs. No tokens in localStorage.
- Alembic 0002 adds only identity tables/constraints/seeds and append-only audit trigger. Reuse PostgreSQL fixture, with controlled cleanup of identity data between tests. No SQLite/mocked repositories. Backend errors redact request validation passwords.
