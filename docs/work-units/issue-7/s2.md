# Issue #7 S2 — overall finalization and withdrawal

Implemented the barcode-level lifecycle behind the public laboratory interface and its HTTP adapter.

- Finalization locks one sample row, validates confirmed identity/tests/report selections, auto-selects sole results, records finalizer/time/history, and audits a truthful SUCCESS result.
- Failed business validation rolls back the attempted transition and is durably audited as FAILURE with structured missing-type or warning details.
- A narrow injected warning source proves acknowledgement semantics without shipping QA/QC rules.
- Finalized scientific data is read-only. Withdrawal requires `laboratory.finalize` plus a reason, records durable history/audit, and restores editing/re-finalization.
- PostgreSQL couples status with finalizer metadata and serializes concurrent finalizers; one succeeds and one receives a stable conflict.
- HTTP endpoints expose report selection, finalization, and withdrawal with the existing authentication/CSRF adapter.

Evidence: initial deep review found the status/metadata invariant gap. The repaired migration passed against a fresh database; all 54 backend tests pass and S2 re-review is PASS.
