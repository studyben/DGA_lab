## Decisions / code-generation plan
Deep laboratory module owns configuration, calibration and QA checks; assets/analysis interfaces unchanged. New LaboratoryConfiguration public application interface and strict Pydantic command models; HTTP is an adapter, auth/CSRF reuse shared requests. New laboratory.configure permission for system_admin/lab_admin, laboratory.read for reads. All writes audited. Configuration does not create arbitrary result schemas: the three implemented test types and their typed field codes remain fixed by ADR0003. Configure type labels/availability, method field labels, unit, decimal places, detection/quantitation limits, optional numeric bounds and allowed qualifiers. Units are one explicitly configured unit per field; no unit conversion or assumed ASTM values. Blank scientific configuration is allowed and displayed as pending.

Methods are create-new-version only, unique (type,version_label); immutable content, independent activation/deactivation. An edit UI clones into a new version, never rewrites old content. Inactive methods remain readable on historical tests and editable only on an existing record already using that version. Catalog type disable blocks new tests, not historical edits. Numeric values bounded by existing NUMERIC(18,6); no NaN/infinity/rounding. Each method has optional immutable QA checklist (code,label,instructions); each test supplies PASS/FAIL/NOT_RUN plus note per configured item, missing means NOT_RUN. This is manual lab QA, not automated scientific threshold analysis, which belongs to later analysis work. Missing/failed checks yield clear per-test warnings; no arbitrary expressions or rule engine.

Instrument catalog: code/name/model/serial and ACTIVE/OUT_OF_SERVICE/RETIRED status. Append-only calibration records use calibrated_on, expires_on (inclusive), outcome VALID/FAILED/UNKNOWN, provider/certificate. At measurement date in America/Chicago choose most recent calibration <= date; future calibration cannot erase historical expiry, null expiry = UNKNOWN. Store selected instrument and calibration evaluation in test quality_snapshot when saving test. Changes later do not rewrite historical tests; explicit editable-test resave reevaluates. Unlinked legacy text is preserved, explicitly NOT_LINKED, never presented as calibrated. Linked inactive instruments reject new selection but existing test remains editable. No certificate upload/automatic acquisition required by this ticket.

QA execution results and calibration snapshot live on laboratory_tests quality_snapshot, with instrument_id FK and method QA configuration in immutable method version. Exposed on TestRecord. Default finalization warnings derive from quality_snapshot (and existing injectable warning_source still supported); each warning identity includes test revision timestamp so acknowledgements of an old result do not cover newly changed failures. Warning acknowledgement remains in existing finalization API, same transaction sample lock and report snapshot; snapshot includes all assessed test quality evidence (including unselected repeats), ack codes/actor/time and full selected method fields. PDF reads snapshot only; show calibration and QA warning descriptions, no live lookup.

Packages are immutable named version templates containing nonduplicate type + default method + required flag. Applying to OPEN oil sample saves template snapshot/required types, replaces prior plan only explicitly; no auto-created blank tests, no deletion of results. No package preserves legacy finalization semantics. Required missing types block finalization with clear separate code; package evolution never changes applied sample. Workbench displays plan and uses defaults on new-test form; method inactive at apply -> reject. This is minimal planned-test capability, not a second workflow engine.

Concurrency: one laboratory configuration advisory transaction lock serializes catalog changes and test save/finalize/package apply. Order: configuration lock then sample row lock, never reversed. Immutable configuration and saved quality snapshot mean later catalog writes cannot change previously stored results. New config mutations use create-only immutable identifiers and uniqueness to reject duplicates; no blind automatic retry after uncertain response. SQL stays inside laboratory; AuditTrail writes shared audit inside same transaction. Read catalog in REPEATABLE READ snapshot.

## Schema / ownership

Required package types have separate required_missing_test_types/required_tests_missing, not the report-result-selection error. Both load and locked finalize consume the same saved package snapshot. Immutable method database guard applies to newly managed versions, allowing unchanged legacy fixture compatibility; production API never edits any version content. Instrument status changes use expected status to reject stale writes. Managed method creation rejects duplicate/missing/unknown field codes and QA codes. Method retire never invalidates existing snapshots.
