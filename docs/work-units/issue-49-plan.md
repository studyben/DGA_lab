## Validation/business decisions

Validate customer/site UUID references explicitly, candidates name-only (casefold trimmed, exact candidate match) with client-visible IDs/customer/location/capacity for comparison. REFERENCE must provide validID, site customer must agree and configured product_line must include requested lines. Proposed different attributes preserved as evidence and produce acknowledged difference warnings, never updates. NEW same-name candidate requires specific warning acknowledgment in addition to NEW reason. No duplicate-name unique constraint. Within-file NEW duplicates also warn; references to same-site multiple rows rejected to avoid conflicting source decisions in one batch. Unknown/blank decisions block until edited. No metadata guessed from notes.

Capacity nonnegative finite NUMERIC(16,6), preserve Decimal text, no rounding; PV energy rejected, missing line capacity empty only, unknown null. Dates strict YYYY-MM-DD, states existing enums; no grid_year or site maintenance enum accepted. source_note<=2000, names/IDs limits follow existing domains, notes preserved whitespace, no truncation. v2 files10MiB, expanded50MiB/200members/150000cells; max500customers/500sites. Reject macros/formulas/external links/encryption/path traversal/duplicate ZIPmembers/unknown or duplicate headers/unsafe identifiers/numeric IDs; do not trust worksheet dimensions. v1 retains2MiB/old parser rules. Valid business batch needs Sites record; customer-only not introduced.

Catalog snapshot captures readable customer/site/line data and revision, not only name/capacity. Under shared table locks, publishing blocks independent inserts/updates so no racing duplicate is missed. Standard lock order avoids inversion with site-maintenance. All new writes additionally serialized by asset graph lock. Individual unique identifiers only, names deliberately not unique.
