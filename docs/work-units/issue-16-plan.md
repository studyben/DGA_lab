## Contracts and decisions

- Analysis owns HealthRules and DeviceHealth public interfaces, HealthRuleInput, HealthError. Existing assets/lab public interfaces remain owners of identity/tree/method/results. Main composes, not business modules. Reuse analysis.read and analysis.write; existing system admin has write. Approval is explicit activation confirmation with reason and authenticated approver, same author allowed.
- One rule version targets type/analyte/exact method UUID/unit and optional physical asset UUID (blank all transformers); priority integer 0..1000, effective aware start and optional exclusive end. Threshold is an explicit comparison GT/GE/LT/LE against nonnegative Decimal(18,6), abnormal severity ATTENTION/WARNING/CRITICAL. One comparison per immutable version; priorities select competing policies, NOT graduated severity bands. For each result the highest-priority applicable rule evaluates; ambiguous same-priority applicability+time overlaps rejected during activation regardless of thresholds. A non-triggered winning comparison means normal; absence of an applicable rule means unassessed. No generic expression language.
- Lifecycle create/update draft with revision, copy any retained version to new draft, activate/retire with expected revision and required reason. Immutable active/retired content. Same-priority overlaps checked under analysis advisory transaction lock, not a check-then-write race. App checks method metadata using laboratory public catalog for analysis; exact configured field/unit validation at save/activation. Retired methods may still evaluate retained results. Optional asset constraint validated via assets transformer_identity.
- Migration 0019_health_rules: health_rule_versions with scalar target/time/priority/numeric comparison/severity/lifecycle/revision/approval metadata; immutable append-only health_rule_events with before/after and reason plus shared AuditTrail in same transaction. health_evaluations append-only with UUID, subject asset FK, semantic input fingerprint, evaluated_at, immutable JSONB evidence (derived assessment, not canonical measurements). Unique subject/fingerprint dedupes repeated reads; no mutable current-health pointer. DB guard forbids deletion, non-draft content edits/invalid state transitions; evaluation/event mutation forbidden; downgrade refuses retained records.
- Assets adds HealthAssetReader.health_assets(actor,root,at): immutable tuple of root+current descendants (UUID, type, serial, asset number,parent UUID), single owner-controlled recursive query, detects cycles/ambiguous paths and fails explicitly, no health semantics in assets. Reuse fixed evaluation time for valid_from<=at<valid_to. Read every asset root separately only through public reader; never cross-table from analysis.
- Laboratory adds method catalog projection requiring analysis.read (not lab write/read) and batched finalized_measurements_for_assets(actor,asset_ids,start,end) to avoid one SQL per transformer. Existing trend seam unchanged, adapter reuses laboratory snapshot decoder. Source only current-token selected snapshots, times UTC.
- DeviceHealth.query(actor,root) read-through evaluates on every request at injected aware clock; no cached current result. Rules held under analysis lock for query; current tree and finalized source read from owners. Before saving evidence re-read tree/source and compare deterministic signatures; retry bounded 3 times on changing input, then 409 health_inputs_changed, not stale normal. No global distributed atomicity claimed; evidence states observed input/evaluation time. Rule activation is serialized and validity evaluated at captured now. Future source sampled_at>now excluded.
- Latest per physical asset/type/analyte before method/qualifier matching; latest ties all retained, worst known severity and incomplete flag. No older fallback. Each transformer with no samples -> UNASSESSED. A latest missing method/units, qualified result, no applicable rule -> explicit reason, unknown coverage. Aggregate own and descendant status separately; worst abnormal wins, else normal if at least one evaluated normal with incomplete marker, else UNASSESSED. Non-transformer self UNASSESSED is not missing coverage by itself (oil health not applicable); descendant transformer no data is missing coverage. No duplicate ancestor source alarm records: store source assessments once per queried evidence, ancestors merely aggregate presentation. No #17 alarm state machine.
- Immutable evaluation payload includes physical source, test/sample IDs, barcode, sample/measured times, value/qualifier/unit/method, selected rule content/version, reasons and evaluated time. Repeated identical content returns retained evidence + checked_at now; old history endpoint GET /health/{id}/evaluations/{evaluation_id} enforces same subject/permission. History never rewritten on rule changes or withdrawal.
- HTTP /api/condition-analysis/rules GET/POST, /rules/{id} PUT, /copy POST, /activate POST, /retire POST; /rule-methods GET; /health/{asset_id} GET; /health/{asset_id}/evaluations/{id} GET. All no-store, permission and CSRF for mutations, validation422, conflict409, source503, absent404; explicit errors/no false empty. Read-through projection persistence only, no user-triggered alarm mutation from GET.
- Frontend minimal rules page /assets/analysis/rules with list, draft/edit/copy, matching method/field/unit selection, explicit bounds/priority/effective local date-times converted ISO, confirmation reason and revision; empty scientific values by default. Safe submit errors preserve inputs; reload on conflict, no automatic write retry. Source config links permission-aware.
- DeviceHealthPanel above attributes loads current health, own vs descendant distinction, red icon+text for abnormal, incomplete coverage and source details/links. Refresh button and 30s nonoverlapping read refresh while mounted; cancellation/late response guard; visible checked/evaluated times, no stale success on failure. Remove hardcoded health from visible attribute output without changing asset ownership. Rules link in analysis navigation. Health overview route may provide asset selection guidance (no global dashboard/#17).

## Plan review corrections and risk ownership

- Current refresh explicitly read-through rather than asynchronous event guarantee: bounded source revalidation and no current pointer prevent late cached conclusions. User-facing checked_at labels; no claim unattended alarm delivery (#17 separately).
- Multiple severity thresholds must use explicit priority: threshold predicate does not choose rule priority; UI documents this, no hidden greatest severity across lower-priority rules.
- Scientific correctness of configured values belongs to authorized maintainer; production defaults prohibited. Capacity/load certification later deployment work. Source/schema failure blocks current health instead of hiding data; no unclassified residual risk.
- No external publication authorized. Completion report: slices/tests/findings/evidence, local preview if prepared, next ready-to-open-draft-PR only.
