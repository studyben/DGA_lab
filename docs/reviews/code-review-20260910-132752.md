### S3-01-未修复-高-界面会静默确认全部QA警告
- **入口/函数**: `WorkbenchPage.finalizeTesting`
- **文件(行号)**: `frontend/src/features/laboratory/WorkbenchPage.tsx:232-240`
- **输入场景**: The configured `FinalizationWarningSource` returns one or more warning codes for an otherwise ready sample.
- **实际分支**: The UI neither displays nor confirms those warnings. Clicking “整体检测定稿” sends the complete server-provided `warning_codes` array as `acknowledged_warning_codes` automatically.
- **预期行为**: Warnings must not hard-block, but the operator must see and explicitly confirm them before the client acknowledges them.
- **实际行为**: The client impersonates acknowledgement; the server sees all current displayed-warning codes as accepted even though the user never saw a prompt.
- **直接证据**: Line 240 copies `data.finalization_assessment.warning_codes` directly into the acknowledgement body; no warning rendering or confirmation branch exists.
- **影响**: QA warnings become operationally invisible and lose their intended human checkpoint, violating the confirmed Issue #7 behavior.
- **建议改法和验证点**: Render a visible warning summary. In `finalizeTesting`, if warning codes exist, require an explicit `window.confirm`; on cancel, make no request. Only after confirmation send those codes. Add a Playwright route-interception test or seeded warning scenario proving cancel produces no finalization and confirm proceeds, without adding real QA rules.
