## Findings

### B2-1-已修复-[中]-Callback address is not part of the immutable tested candidate

- **Controller disposition**: accepted; fixed and statically re-reviewed at 20261002-032032. The scenario and original evidence below describe the pre-fix snapshot.
- **Re-review evidence**: Migration 0029 adds callback_url without assigning a mutable default to historical rows. OidcService._config rejects null legacy callbacks, and new save_candidate snapshots the validated candidate callback. Deployment OIDC_CALLBACK_ORIGINS is consumed by main.py:81, stored in _callback_origins, and enforced by _checked_callback on save and load. The configured default supplies an origin only when no explicit allowlist exists; it is not substituted into existing candidate rows. Both TEST and LOGIN authorization/redemption use config['callback_url'] (oidc.py:156/:202/:268/:296). Both HTTP start routes pass the already validated Origin to _start_origin (oidc_http.py:76/:81). Settings exposes and displays the candidate callback. The new targeted test verifies an allowed non-default callback, forbidden origin/path/query, matching authorization/token redirect_uri and initiating-origin mismatch rejection.
- **入口/函数**: Settings candidate creation -> OidcService.save_candidate -> start_test/complete_test -> activate -> start_login/complete_login.
- **文件(行号)**: backend/dga/shared/auth/oidc.py:14 (CandidateInput), :79 (candidate persistence), :130/:176 (TEST authorization/exchange), :241/:269 (LOGIN authorization/exchange), :200 (activation); frontend/src/features/identity/OidcConfigurationPage.tsx candidate form. Line references refer to the reviewed pre-fix B2 snapshot.
- **输入场景**: An administrator needs to update the application callback address through Settings, or a tested candidate/proof already exists and the deployment OIDC_CALLBACK_URL changes before activation or callback completion.
- **实际分支**: Candidate input/storage contain issuer, client ID and encrypted secret, but no callback. Authorization and token exchange use mutable service-level self._callback. Activation checks the candidate/proof IDs without capturing the callback used by the proof.
- **预期行为**: ADR-0007 requires online Settings maintenance of the callback address. The exact candidate tested must be the one activated; historical candidates and flows must retain their callback semantics. Fixed backend route and deployment origin restrictions must remain enforced.
- **实际行为**: Settings cannot edit the callback; changing the deployment default changes the redirect_uri used by an existing candidate and flow, and a prior proof can authorize activation without testing that new callback.
- **直接证据**: CandidateInput exposes only issuer/client_id/client_secret; save_candidate INSERT omits callback; all four authorization/exchange call sites consume self._callback. ADR-0007 states that access parameters and the application's callback address support online Settings maintenance. The approved plan supersedes only the ADR's unresolved protocol choice, not this requirement.
- **影响**: Missing agreed capability, runtime redirect mismatch, and loss of exact candidate/test/activation correspondence.
- **建议改法和验证点**: Persist callback_url in each immutable candidate; require the fixed /api/auth/oidc/callback path and a deployment-managed allowed-origin list. Authorization and redemption must both use the candidate value. Defaults may prefill new candidates but must not alter historical candidates. Explicitly migrate or replace old candidates rather than using a mutable runtime fallback. Validate initiating browser Origin equals candidate callback origin to preserve host-only binding cookies. Test different allowed callback origins, disallowed origins, old candidate/flow behavior after default changes, and mismatched initiating origin rejection before navigation.
- **修复风险（低/中/高）**: 中; immutable historical rows and in-flight flows require explicit migration semantics.
- **严重程度（低/中/高/严重）**: 中.

### B2-2-已修复-[中]-Callback query parameters remain exposed through Nginx error logging

- **Controller disposition**: accepted; fixed and statically re-reviewed at 20261002-032032. Actual proxy fault-injection verification remains a named C gate, not claimed complete here. The scenario and original evidence below describe the pre-fix snapshot.
- **Re-review evidence**: frontend/nginx.conf applies error_log /dev/null to the entire /api/auth/oidc/ location and uses oidc_safe access logs containing only method/status/upstream status/timing. No URI or query variable appears in that format. The Uvicorn access filter now matches the entire OIDC prefix, covering the earlier exact-path/trailing-slash gap. Query-free access records retain failure visibility after the unsafe error channel is suppressed.
- **入口/函数**: Browser GET /api/auth/oidc/callback -> Nginx reverse proxy -> unavailable or failing API upstream.
- **文件(行号)**: frontend/nginx.conf:7-14; backend/dga/shared/auth/oidc_http.py OidcAccessLogFilter. Line references refer to the reviewed pre-fix B2 snapshot.
- **输入场景**: A callback containing authorization code/state encounters connection refusal, upstream timeout or premature upstream termination; noncanonical callback paths such as a trailing slash also need explicit coverage.
- **实际分支**: The exact callback location disables access_log but leaves the independent inherited error_log channel enabled. The Python filter only sanitizes Uvicorn access records for the exact path.
- **预期行为**: Callback code/state must not be retained in request/error logs, including failure paths.
- **实际行为**: Nginx upstream errors attach the original request line, including its query string, to error logs even when access_log is off.
- **直接证据**: The callback location contains access_log off and no corresponding error-log protection. Nginx ngx_http_log_error_handler appends r->request_line to error output (official source lines 3916-3917 at review time). The error_log directive is independent of access logging.
- **影响**: Authorization codes and state can be copied into persistent proxy/container logs during ordinary dependency failures. PKCE limits redemption but does not satisfy the required secret-redaction boundary.
- **建议改法和验证点**: Configure a callback-specific error path that cannot record query values; protect noncanonical callback variants as well. Preserve useful sanitized failure observability separately. Verify with synthetic canary code/state and an unavailable or failing isolated upstream, checking both proxy and application logs. Do not use real credentials or production outages for this test.
- **修复风险（低/中/高）**: 中; suppressing unsafe log channels must not be mistaken for retaining sanitized operational evidence.
- **严重程度（低/中/高/严重）**: 中.
- **Primary sources**: [Nginx error_log documentation](https://nginx.org/en/docs/ngx_core_module.html#error_log); [Nginx request/error logging implementation](https://raw.githubusercontent.com/nginx/nginx/master/src/http/ngx_http_request.c).
