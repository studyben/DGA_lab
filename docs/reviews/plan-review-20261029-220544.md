## Findings

### 01-未修复-[中]-历史未决文件可阻断完整工作清单的同批续办

- **状态**: accepted-candidate；由 controller 裁决。
- **位置**: plan lines 148–149, 164, 178, 183–185, 189, 195–208, 211; S1/S2 recovery tests at 260/272.
- **问题类型**: 契约缺失 / 并发恢复风险 / 状态机漏洞 / 测试缺口。
- **当前写法**: validate 要求完整 active 工作文件，同时写了没有限定范围的 `no PENDING receipt`（178）。所有 PENDING 文件必为 inactive（148、198），工作清单却只由 active RECEIVED 文件构成（195）。操作及结果是原 actor 私有（164、183）；过期上传只能按原 key、相同 intent 重新取得 lease（205–206）；没有 cancel/delete，较广 orphan reconciliation 留给 #60（185、189、211）。
- **反例/失败场景**:
  1. A 有效获权时预留 WORKBOOK；PENDING operation/file 已提交，尚未完成 provider/receipt 收尾就退出或崩溃，之后 A 被停用或撤权。
  2. B 仍有当前 laboratory.write，按自己的 operation key 为同一批次上传一份已确认原件。该角色尚无 active 文件，所以 B 的 RECEIVED 文件成为 active，工作清单 COMPLETE。
  3. 如果实现按 178 的字面检查该批次任何 PENDING，A 的历史 inactive 行使 B 的 validate 永远返回 `files_pending`。
  4. B 不能作为 A 查询/续传原 actor-private operation，A 可能永不回来；#52 又没有取消/删除。用户只能重建批次或等 #60，虽然当前已具备完整、有效、明确选择的工作文件。
- **为什么有问题**: 这不是已实现 bug 的断言，而是 plan 留给实现者的实质门控歧义。它把不可恢复的历史上传状态与独立可用的当前工作清单耦合。冻结 D8 要求超时查询原操作并同批续办，权限与保留原件要求也不允许直接替 A 补成功或丢弃原件。#52 自身包含 first-entry receipt/recovery，不能把基本同批替代续办推给 #60。
- **直接证据**: 178 的 `active exact workbook or samples/tests pair required, no PENDING receipt`；148 的 `CHECK active=>state=RECEIVED`；164 的 `Batch data is readable to any currently authorized lab writer; operation keys/results remain original-actor-private`；185 的 `no cancel endpoint (#60)`；195 的 `manifest_state ... from active RECEIVED roles`；206 的相同 pending key/相同 digest reclaim；208 的撤权后不完成 receipt；冻结 spec D8 lines 215/219 的同批恢复与 actor-key 持久结果、251 的不删除未决对象及 253 的后台当前权限约束。
- **影响**: 实施 Agent 可能生成一个正常单用户 happy path 通过、跨 actor/崩溃后永久阻塞的校验入口；完整工作清单无法验收，导致重复批次和后续返工，或诱使实现绕过 actor 权限/删除未知对象。
- **建议改法和验证点**:
  - 明确校验依赖选定 active working manifest；它必须完整、RECEIVED 且字节/hash 元数据已确认。缺少必需角色用 `active_files_incomplete` 等明确错误。
  - 明确无关 inactive 历史 PENDING/RETRYABLE 不阻塞一个完整选定清单，只作为未决 receipt 历史显示。保留原 actor 的 key/result 权限、对象和恢复元数据。
  - 允许其他当前获权 writer 以自己的 operation 提供并明确选择另一个验证过的原件；不用增加一般取消、孤儿清理或代原 actor replay。
  - 按现有 revision/token 策略测试：晚到 receipt 只能按约定保留/递增历史及使旧校验失效，不能替换已选 active 文件或让陈旧结果成为 current。
  - 补真实 PostgreSQL 的公开应用接口测试：A 预留后崩溃/lease 过期或撤权；B 提供完整 active 清单；同批 queue/process/preview 成功；A 原未决操作/对象仍保留且 actor-private；晚到结果与并发 validation 不污染当前快照；正式业务数据无新增。
- **修复风险（低/中/高）**: 低；收窄门控契约并增加状态组合验收，不需要扩展产品权限、数据库总体设计或未来票范围。
- **严重程度（低/中/高/严重）**: 中（P2）。
