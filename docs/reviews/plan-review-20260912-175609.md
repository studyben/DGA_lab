## Findings and fix/re-review

### 1-已修复-[中]-XLSX XML expansion must be guarded before parser allocation

- **位置**: workbook resource limits / dependency decision.
- **问题类型**: trust boundary / incomplete dependency contract.
- **当前写法**: limits and formula rejection, but parser dependency was not explicitly chosen.
- **反例/失败场景**: a small ZIP/XML payload expands inside an unsafe XML parser before row-count checks run.
- **直接证据**: [openpyxl security notice](https://pypi.org/project/openpyxl/) requires defusedxml for XML expansion defense; repository has neither dependency yet.
- **影响**: denial of service on upload.
- **建议改法和验证点**: pin openpyxl with defusedxml, verify ZIP metadata and bounded decompressed XML before workbook loading, add adversarial file-input tests. Disable external links; no formulas evaluated.
- **修复风险**: low; **严重程度**: medium.
- **Decision**: accepted. Plan implementation dependency is openpyxl + defusedxml, with preflight archive/XML guards. Test through public submit, not parser internals.

Re-review: dependency/guard commitment now explicit here and binding on S1. The original incremental-scope finding is 已修复 by user confirmation; no further product question.
