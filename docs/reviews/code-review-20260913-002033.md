## Findings

### 1-已修复-[中]-Configured scalar result units and display precision do not reach PDF output

- **入口/函数**: LaboratoryReports._selected_result -> render_report_pdf.
- **文件(行号)**: backend/dga/laboratory/reports.py:489; backend/dga/laboratory/report_pdf.py:125-130,180-189.
- **输入场景**: Create a configured MOISTURE method whose field code is MOISTURE, unit is a laboratory-provided unit, and display_decimal_places is 2; save 8.50, finalize and generate PDF. BREAKDOWN_VOLTAGE follows the same path. DGA exposes the decimal-place portion of the defect.
- **实际分支**: _selected_result stores configured fields with semantic field codes, but scalar result values remain under the key `result`. The renderer looks up fields using that result key, misses the MOISTURE/BREAKDOWN_VOLTAGE field, and falls back to an empty field. _measurement accepts only unit, not display_decimal_places.
- **预期行为**: A report generated under a configured method displays the configured result label and unit and respects that method's saved display precision without looking up current configuration.
- **实际行为**: Scalar PDF measurements show RESULT and no configured unit. Configured decimal places are persisted in the new snapshot but ignored by rendering; database NUMERIC scale can surface as 8.500000 instead of 8.50.
- **直接证据**: reports.py scalar branch constructs `result = {'result': ...}`; new line 489 retains code MOISTURE or BREAKDOWN_VOLTAGE in fields. report_pdf.py:125 builds a code-keyed mapping; line127 gets `fields.get(code.lower(), {})`; line130 passes only measurement and unit. _measurement formats the raw string. No display_decimal_places consumption exists in this renderer.
- **影响**: Formally configured scientific result units disappear from two supported report types; precision promised by the method does not govern delivered reports. The scalar mapping predates S2, but the new configuration-to-report capability directly depends on it and S2 adds snapshot fields without wiring their final consumer.
- **建议改法和验证点**: Make snapshot scalar result keys match semantic field codes, or explicitly map scalar result to its single typed field in the renderer. Preserve compatibility for existing schema-v1 snapshots deliberately. Format numeric values from snapshot decimal places with Decimal, preserving qualifiers and not changing stored values. Add actual rendered PDF assertions for configured moisture and breakdown units/labels plus DGA and scalar precision; asserting snapshot presence alone does not cover this failure.
- **修复风险（低/中/高）**: 中; existing schema-v1 report snapshots must remain renderable.
- **严重程度（低/中/高/严重）**: 中.
