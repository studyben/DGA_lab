## Main adversarial review

- Login input -> origin -> row-locked account -> hash verification/status/throttle -> transaction audit -> explicit redacted response/cookie. Unknown users have nullable actor and generic failure. No token/password serialization.
- Session -> hashed lookup -> active account/expiry -> fresh roles/grants -> public module guard. Pending-password sessions blocked from registry and module APIs; frontend is not the security boundary.
- Password change -> origin/CSRF -> user lock -> reread session -> verify old password/reject reuse -> update hash and revoke all sessions -> new session/audit in one transaction. Competing changes have one winner. Logout serializes with credential changes and is idempotent for revoked tokens.
- Operator status/roles -> global advisory lock -> fresh admin authorization -> target lock -> state/audit mutation. Disable/lock revokes sessions; enabling does not resurrect tokens. No management command exposed as public registration HTTP.
- Frontend -> initial pending gate -> login/mandatory change/forbidden; interval/focus refresh and revision counter avoid stale responses overwriting newer state. Failed checks show retry; no browser token storage or untrusted return redirect.
- Migration -> stable role seed -> append-only audit update/delete guard; test downgrade/upgrade only against isolated PostgreSQL. Normal startup uses forward migration with existing volume retained. No test seeds in normal DB.
- Ownership/overcoupling pass: transport handles headers/cookies, identity owns authorization truth, modules own capabilities, frontend owns affordances. No downstream fallback recreates upstream authority. Narrow interfaces retained; no speculative generic framework.
