### 01-未修复-[中/P2]-文件读取完成前的双击可生成两个上传意图并覆盖恢复槽

- **文件(行号)**: frontend/src/features/laboratory/ImportPage.tsx:209–214,186–188; importIntent.ts:fileMetadata/prepareIntent/retainIntent.
- **输入场景**: 用户选择一个合法文件后快速双击保存；读取/计算文件摘要仍未结束。
- **实际分支**: upload先检查intent/busy，随后await fileMetadata；busy与intent仅在该await之后的run才设置。两个调用可同时通过检查，再分别prepareIntent产生不同key；run不检查是否已有正在执行的intent，后一次retainIntent覆盖同一actor的单一sessionStorage槽。
- **预期行为**: 一次用户提交只能占用一个可恢复意图。重复点击应共享原key或不产生第二个保存请求，原结果未知时尤其不能丢失其key。
- **实际行为**: 两个不同key的POST均被正常接收，产生两个文件和两次revision，前一个待恢复key可被覆盖或被另一个完成回调清除。
- **直接证据**: 独立真实Chrome/生产bundle探针.cache/issue52-tests/review-s1-frontend-doubleclick.cjs仅将File.arrayBuffer延迟500ms，20ms双击后观察到2个/files POST、不同Idempotency-Key、两份RECEIVED、revision=2；batch7e0682ad-cb1f-48a7-b117-187b24a26dbb。没有mock HTTP/domain。
- **影响**: 重复上传与恢复元数据丢失；破坏从第一个写入口起的基本幂等和未知结果恢复契约。服务端对不同key正常接收不是服务端去重缺陷，提交占用所有权在前端。
- **建议改法和验证点**: 在首个异步文件读取前同步占用in-flight guard，所有提交入口使用一致占用规则，并在确定的finally边界释放；不能只等React state render。增加延迟文件读取+双击浏览器用例，断言1POST/1file/1revision；再覆盖响应丢失后仅原key保留、可查询/重试。
- **修复风险**: 中；需覆盖成功、存储失败、超时、重新选择原件、显式重试及锁释放，避免形成新死锁或清空未知intent。

### 02-未修复-[中/P2]-服务端绑定前的明确输入拒绝可永久锁住该账号暂存入口

- **文件(行号)**: frontend/src/features/laboratory/ImportPage.tsx:16–20,188,200,226–232,245–246；backend/dga/laboratory/import_http.py:command_body及create；import_contracts.py:CreateImport.coherent。
- **输入场景**: 在来源时区填america/chicago。Chrome Intl将其作为合法时区接受，但Python ZoneInfo对名称大小写敏感而拒绝。

- **预期行为**: 权威服务器已明确拒绝且未产生写入的输入应能经显式确认后更正；保留404/503/认证及未知COMMIT场景的原意图安全性，不能将不确定结果任意清空。

- **修复风险**: 中；涉及拒绝与不确定结果的公开契约，必须防止错误清理已提交意图或为未知请求生成新key。
