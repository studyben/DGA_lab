### AGG-01-未修复-高-自动或隐式报告结果变化没有选择审计事件
- **入口/函数**: `LaboratoryWorkbench.finalize`, `update_test`, `remove_test`
- **文件(行号)**: `backend/dga/laboratory/workbench.py:312,351,441`
- **输入场景**: A sole result is auto-selected during finalization, or a selected result is changed to another test type or removed.
- **实际分支**: Each path changes `selected_for_report`, but only explicit `select_report_result` appends `REPORT_RESULT_SELECTED`. The other paths emit finalization/test-update/test-removal events without an explicit report-selection change.
- **预期行为**: Issue #7 requires selection changes to be audited. An audit consumer should be able to identify every transition of the report-result choice, including automatic selection and clearing.
- **实际行为**: The selected report dataset changes without a selection-specific audit event; it must be inferred from unrelated actions and cannot distinguish an update/removal that did not affect selection.
- **直接证据**: The writes at lines 312, 351 and 443 have no adjacent selection-change audit; the only `REPORT_RESULT_SELECTED` append is line 395.
- **影响**: Incomplete traceability for the exact data later used in a report; acceptance is only partially met.
- **建议改法和验证点**: Add `REPORT_RESULT_CLEARED` for selected type-change/removal and append `REPORT_RESULT_SELECTED` for every sole-result auto-selection inside the finalization transaction. Assert exact events through the public audit query for all three paths.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### AGG-02-未修复-高-有定稿数据时0006降级后无法重新升级
- **入口/函数**: Alembic `0006_laboratory_finalization.downgrade/upgrade`
- **文件(行号)**: `backend/migrations/versions/0006_laboratory_finalization.py:13-32,53-64`
- **输入场景**: A database contains an application-finalized sample, is downgraded from 0006 to 0005, then upgraded to head again.
- **实际分支**: Downgrade drops finalizer columns but leaves the pre-existing 0005 `testing_status='FINALIZED'`. Re-upgrade adds nullable finalizer columns and immediately applies a check that requires both values for every finalized row, so the migration fails.
- **预期行为**: The documented migration cycle should be reversible in the isolated test database even after exercising the new state. Since 0005 has no supported finalization command/metadata, downgrade should normalize affected rows to `OPEN` before dropping 0006 facts.
- **实际行为**: A valid lifecycle state created by this issue makes its own downgrade/re-upgrade path fail.
- **直接证据**: Downgrade never updates `oil_samples.testing_status`; upgrade's `testing_status_and_finalizer_consistent` rejects the resulting finalized/null rows.
- **影响**: Broken rollback recovery and failed migration rehearsal once finalization has been used.
- **建议改法和验证点**: In downgrade, set `testing_status='OPEN'` for finalized rows before dropping finalizer metadata. Add an Alembic round-trip test starting from a publicly finalized sample, then confirm upgrade succeeds and the sample is open with its test records intact.
- **修复风险（低/中/高）**: 中（downgrade intentionally loses 0006 lifecycle state）
- **严重程度（低/中/高/严重）**: 高
