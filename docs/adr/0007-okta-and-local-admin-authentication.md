# 使用 OIDC 员工登录并保留独立本地管理员恢复入口

承接原工作区 ADR-0007 与用户已确认的 Issue #18 范围：公司身份认证采用 Okta OIDC，业务授权继续由 DGA Lab 拥有。仅实现后端 Authorization Code + PKCE；不实现 SAML、双协议或目录同步。保留不依赖 Okta 的本地管理员入口，避免身份提供方故障导致系统无法恢复。

## 决策与后果

- 六种业务角色可组合，不构成线性等级。系统管理员、实验室经理、分析员、现场工程师、资产经理和管理层的精确权限及管理边界见[操作手册](../identity-operations.md)。外部 roles/groups 声明不映射业务权限。
- 只接受公司 IT 为本应用分配的员工。外部身份由 issuer + subject 关联稳定内部账号；首次成功验证授予现场工程师并记录来源审计，后续不覆盖角色或停用状态。邮箱/用户名冲突不得自动合并，系统管理员通过近期已验证身份明确关联。
- 本系统停用立即撤销会话；再次 OIDC 登录不重新建替代账号。Okta 侧停用/撤销分配后的存量会话最多存续八小时：自最近一次验证起绝对计时，不刷新令牌、不滑动续期。紧急撤权必须同时在本系统停用；真实 IT 联调须验证不再签发可接受的新登录。
- 本地恢复入口 `/login/local` 始终独立于 OIDC 可用性。最后一个启用、有本地密码的系统管理员不可停用、锁定或降权；外部身份管理员不计入这一保护。可信服务器操作员可交互重置已有本地管理员密码，强制改密并撤销旧会话，但不能复活已停用账号。
- 旧 UUID、历史归属、密码和角色分配保留；`management_readonly` 留作不再分配的兼容角色，不猜测逐账号映射。新本地凭据仅供恢复管理员。部署先核对逐账号角色影响报告，再显式应用迁移。
- 系统管理员在线保存不可变候选（issuer、client ID、加密 secret、固定路径的回调地址），完成测试后在十五分钟内明确启用。证明绑定同一管理员及精确候选，失败不替换现行配置。回调 origin 必须在部署白名单，且与发起浏览器 origin 一致；新候选默认值不改变旧候选。修改页面不会自动修改 Okta 注册、DNS或反向代理。
- 加密密钥由部署持有并独立备份，不保存在数据库/源代码。账号、外部身份和候选配置在 PostgreSQL 持久化。缺少 IT 配置时仅完成独立部分；模拟协议测试和测试域名映射不能充当真实 Okta 验收。

本文件仅整理本 work unit 的已确认决策，不覆盖原工作区未提交领域文档。ADR-0007 原“协议待 IT 确认”由用户已选择 OIDC 的决定取代；#18 → #19 → #20 顺序不变，当前没有批准开始后续工单。
